## 实验直接暴露并已修正的问题

1. 预约场景原先允许模型在会议前一天启动设备。Prompt 已增加任务范围和会议阶段
   约束，验证也会拒绝提前设备动作；修正后 Tool 从 11 降到 6。
2. MQTT 加速发布退出时会丢最后一条消息。Publisher 现在等待 QoS 发布确认，真实
   Mosquitto 回环测试已验证温度、湿度和 CO₂ 三条消息全部到达。
3. 人数场景缺少聚合人数 Tool 和明确时间边界，模型曾推进约 15 小时并留下通风
   设备。已增加 `OccupancyApp.get_room_occupancy()`，明确 6 个阶段并统一使用专用
   通风设备；修正后约 81 分钟结束并通过验证。
4. HVAC 关闭命令仍校验无物理意义的目标温度，导致一次直觉合理的关闭调用被拒绝。
   现在关闭状态会忽略并清除目标温度。

## 尚未解决的主要问题

温湿度协调需要 Controller 层的有限状态/迟滞终止策略，而不是继续增加 Prompt：

```text
precondition -> observe -> within target for N checks -> maintain/stop -> final verify
```

需要限制最大模拟时长、连续无改善次数和重复命令，并把“已经达标但未清理”作为
显式控制状态。下一轮对比实验应在实现该策略后进行，并至少使用多个随机种子。
